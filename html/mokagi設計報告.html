三、設計錯誤 / 缺陷（需修正）

缺陷 1（致命）：asyncio.Lock() 綁定 event loop，多線程多 loop 下會崩 P0

位置：core/config.py:38-42 → get_config_lock() 返回 asyncio.Lock()；get_agent_config()（config.py:134）內 async with get_config_lock()。

但 mok_web.py:153 用 async_mode="threading"，且 /api/chat（mok_web.py:495-612）每請求開一個 thread + asyncio.new_event_loop()。

當兩個用戶並行、各自在不同 loop 同時觸發 get_agent_config → 第二個 loop 碰到第一個 loop 綁定的 lock → RuntimeError: <Lock> is bound to a different event loop。

# 現況（錯）
_config_cache_lock = None
def get_config_lock():
    global _config_cache_lock
    if _config_cache_lock is None:
        _config_cache_lock = asyncio.Lock()   # ← 綁定當前 loop
    return _config_cache_lock

# 建議（配置加載是同步檔案 I/O，用同步鎖即可，跨線程/loop 都安全）
import threading
_config_cache_lock = threading.Lock()
def get_config_lock():
    return _config_cache_lock
# get_agent_config 改用：with _config_cache_lock:  （去掉 async with）

缺陷 2（致命）：全局單例 _openai_client 綁定 loop，多線程互相覆蓋 P0

位置：mokagi.py:959-985 _get_openai_client()。全局 _openai_client + _openai_client_loop，偵測到 loop 不同就重建。

多線程並發時會競態：線程 A 重建 client（綁 loop A），線程 B 又偵測不同重建（綁 loop B），線程 A 手裡的 client 實際已被 B 覆蓋 → 跨 loop 呼叫 OpenAI 掛起/報錯。

# 建議：按 loop 隔離，每個 loop 一個 client
_openai_clients = {}   # {loop_id: client}
import threading as _t
_clients_lock = _t.Lock()

def _get_openai_client(api_key, base_url):
    loop = asyncio.get_running_loop()
    lid = id(loop)
    with _clients_lock:
        c = _openai_clients.get(lid)
        if c is None or loop.is_closed():
            c = openai.AsyncOpenAI(api_key=api_key, base_url=base_url, ...)
            _openai_clients[lid] = c
    return c

四、「24 小時多工並行」的落地建議

真正的並行瓶頸不是「開幾個進程」，而是共享可變狀態 + event loop 綁定。修復順序：

  1. 先修 P0 兩項（config 鎖改 threading.Lock、OpenAI client 按 loop 隔離）——不修，並發一高就崩。
  2. launcher 補齊前端：確認 wa/ws 後加 start_wa() 或 start_ws()，統一由 launcher 拉起。
  3. 每 Agent 的 TG bot 已是獨立進程 → 天然並行；Web 端靠 thread + 獨立 loop 並行，修完 P0 後即可穩定多工。
  4. 若要多 Agent 跨進程協作（一個任務分給多個 agent），目前 job/workflow 工具已有 handover/takeover 概念，但需驗證其多進程安全性。
  5. 加 pm2 start launcher.py 或 systemd 常駐 + 自動重啟，確保 24 小時不中斷（目前主機上 pm2 未安裝、且無 mok_* 進程在跑）。

五、結論一句話

mokagi.py 的「統一核心 + 多用戶/多 Agent 參數化」骨架沒有錯，錯在全域共享狀態用了綁定 event loop 的 asyncio 物件（config 鎖、OpenAI client），以及launcher 沒有把你要的公開前端全部拉起。修掉 P0 兩項，就能安全支撐「24 小時多工並行」。
