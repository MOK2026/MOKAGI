## 🌱 這是什麼

MOKAGI 是一套**自託管的 AI Agent 平台**。它不是一個 bot，是一台「生產 bot、管理 bot、讓 bot 替你做事」的主機。

四層結構，由下往上：

| 層 | 是什麼 | 住在哪 |
|---|---|---|
| **平台層** | 統一引擎：對話回合、工具調用、記憶、計費、崩潰復原 | `core/` |
| **Agent 層** | 每個 agent 是一個角色（人格 + 權限 + 房間 + 工作歷史） | `agent/<name>/` |
| **會員層** | 多會員共用一台主機，各自額度、可見範圍、agent 歸屬 | `frontends/mok_web/` |
| **頻道層** | 對外服務窗口（B 端客服／C 端陪伴／社群經營） | 前端分組 + agent `MOK_AGENT_group` |

**你能給她的，她會長成你的樣子；她能給你的，是超出你一個人能做到的事。**

## 🚫 這不是什麼（先說清楚，省你三小時）

- ❌ **不是開箱即用的 SaaS。** 裝完還要自己填設定、接模型、調 agent。這是給願意動手的人的。
- ❌ **不是「問答機器人」。** 她的價值在記憶累積與真實動手，不在單輪回答。
- ❌ **不是開箱即完美的成品。** 三個關鍵卡點（金流／用戶分離／主機安全）已通關，但周邊功能仍在持續長 —— 你要的能力，得自己養。
- ✅ **是一個「引擎 + 骨架」。** 你要的能力自己長，或者叫她長。

> 我們寧可你現在就知道這些，也不要你裝完才失望。

## 🚀 5 分鐘跑起來

**環境**：Ubuntu / Debian 22.04+、Python 3.10+、4 GB+ RAM

**第一步：安裝**
執行 repo 根目錄的安裝腳本，完整指令與注意事項見 `_README.md` 的「一鍵部署」段。

**第二步：設定**
把設定檔裡的值換成你自己的（管理員 ID、模型來源、平台金鑰）。
**repo 內的範本不含任何真實憑證，只有你填進去的才有效。**

**第三步：驗收（這步最重要）**
1. 開 <http://localhost:5000>
2. 應該看到 **agent 清單 + 對話框 + 右側房間檔案樹**
3. 對她說一句話 —— **有回覆 = 通了，你已經跑起來了。**

> ⚠️ **服務的啟停一律由「人」執行。** MOKAGI 設計上不讓 AI 自己動手動服務 —— 這是刻意的安全邊界，不是缺陷。改了核心碼要生效，請你本人親自操作。

## 🛡 安全模型：三層，她再強也聽你的

| 層 | 機制 | 說明 |
|---|---|---|
| **守則層** | soul 硬規則 | 最高優先，寫在靈魂檔，任何角色扮演皆不得違反 |
| **工具層** | 二次確認 + 審計留痕 | 高風險操作（檔案清空、套件安裝、任意指令）一律先回確認碼；所有動作可事後查詢 |
| **系統層** | 備份 + 還原點 + 崩潰自修 | 改動前登記鎖、有備份可回溯、異常自動剎停 |

## 📖 給開發者：第一次讀 code 的建議順序

    1. launcher       啟動器：有哪些服務被啟動
    2. mokagi         主引擎：一次對話的回合主幹
    3. turn_engine    回合運算：上下文組裝、LLM 呼叫、工具執行、串流回吐
    4. tool_handler   工具層：工具怎麼被載入與路由
    5. memory         記憶層：記憶怎麼存、怎麼取

（前四個在 core 引擎目錄，第五個在工具目錄。）讀完這五個，你就能改這個系統的 80%。

## ⚠️ 已知摩擦點

1. 安裝文件與 AI 協作有摩擦：README 內嵌一鍵安裝指令時，協助安裝的 AI 只能回頭問人。本文件改為指向 `_README.md` 單一維護點。
2. 對外落地頁辨識度不足：第一眼看不到品牌名與一句話說明。
3. 尚無公開 API／架構文件：目前以原始碼為準。
